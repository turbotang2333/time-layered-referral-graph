# Time-Layered Referral Graph

一个用于展示“多层级关系 + 时间先后”的前端可视化模板。

它来自一次邀请裂变页面的前端实践，但这个仓库只保留通用方案：如何把一批带上下级关系、带发生时间的节点，放进一张可阅读的时间轴关系图里。

## 这个方案解决什么问题

普通关系图容易乱：节点一多，线会缠在一起；普通时间线又看不出谁带来了谁。

这套方案的核心判断是：

> 层级是结构，时间是过程。

所以图的基础布局是：

- 横轴：关系层级。左到右依次是入口、一级、二级、三级……
- 纵轴：事件时间。越晚发生，越靠下。
- 连线：从上级节点连到下级节点，表示一次关系传递。
- 节点：表示一个用户、一次提交、一次传播事件，具体含义由业务决定。

这样读图时，用户先看到“传播从哪一层走到哪一层”，再顺着纵向时间看它什么时候发生。

## 为什么不是普通树图

树图适合回答“谁是谁的下级”，但不擅长回答“这些关系是什么时候发生的”。

如果只在树节点旁边写时间，时间会变成备注；用户仍然需要来回扫文本，才能判断先后。

这套图把时间变成真正的位置：

- 时间早晚由纵向坐标表达；
- 同一天、跨天、整点刻度都在轴上；
- 某个下级节点如果视觉上跑到上级前面，用户会立刻觉得不合理。

因此布局规则必须保证：下级节点不能在它的直接上级之前出现。

## 为什么不是桑基图

桑基图适合看每层人数流量，例如入口多少、一级多少、二级多少。

但它会牺牲单个节点的关系，不适合回答：

- 某个人后续带来了哪些人？
- 这个分支在什么时间扩散？
- 某条链路上级是谁、下级是谁？

所以本方案保留每个节点，只在必要时做局部聚合。

## 布局规则

### 1. 层级固定为横向列

每个节点根据上级关系计算层级：

- 没有上级：入口层；
- 上级在入口层：一级；
- 上级在一级：二级；
- 继续向右递增。

层级列固定，不随缩放改变。这样用户始终知道“左边是来源，右边是传播出去的人”。

### 2. 时间固定为纵向轴

每个节点根据事件时间定位在纵轴上。时间轴按小时绘制刻度，跨天时用明显分界线标出。

缩小时可以把刻度从 `1 小时/格` 切换为 `2 小时/格`，让整体更紧凑；放大后再恢复更细的刻度。

### 3. 密集时间点横向错开

如果很多节点在接近的时间提交，不能把它们硬往下挤，因为那会破坏真实时间顺序。

正确处理方式是：

- 时间位置仍然由真实时间决定；
- 同层节点如果会重叠，就围绕本层主轴做横向轻微错开；
- 缩放时间轴后，纵向距离变大，横向错开逐步收回主轴。

简单说：拥挤时横向散开，看清后自动回到本来的层级列。

### 4. 低价值密集入口可以聚合

入口层通常会有很多“没有后续传播”的节点。它们都是真实数据，但逐个铺开会挤占画面。

推荐做法：

- 保留有后续关系的入口节点；
- 没有后续关系的入口节点，按时间段聚合成小块；
- 放大到足够倍率或点击聚合块时，再展开为具体节点。

这样不会丢数据，也不会让无分支节点淹没有价值的传播链。

## 交互规则

### 滚轮缩放时间轴

滚轮主要控制纵向时间密度。缩小时看到全局，放大后看密集时间段。

### 拖动平移

拖动空白区域可以上下浏览时间线，也可以左右查看不同层级列。

### 点击节点聚焦完整链路

点击一个节点后，高亮：

- 它的所有上级，一直到入口；
- 它的所有下级，包括后续多级分支；
- 这些节点之间的连线。

其他节点淡化但不消失。再次点击同一节点取消聚焦。

这个交互适合从全局视图切到“单条链路核查”。

### 层级级联收起

点击某一层级的收起按钮时，该层以及更深层级一起隐藏。

例如收起二级时，二级、三级、四级都会隐藏。原因是更深层级依赖前面的层级，单独保留会失去上下文。

### 悬浮卡片分行展示

鼠标移到节点上时，用分行卡片展示信息：

- 标识：节点短标签；
- 来源：入口、一级、二级等；
- 时间：事件发生时间；
- 直接下级：直接带来的节点数量；
- 后续范围：后续节点最早到最晚的时间。

每行用不同底色标签区分信息类型，避免堆成一句很长的文字。

## 视觉编码

推荐只使用少量、稳定的视觉含义：

- 颜色：表示层级；
- 颜色深浅：表示直接下级数量；
- 圆点大小：辅助表示直接下级数量；
- 线条深浅：默认展示全局关系，聚焦时突出当前链路。

不要把过多含义塞到颜色里。颜色首先服务于“这是第几层”。

## 后端如何对接

前端不需要知道数据库、业务表或服务器细节。

后端只需要定期生成一份脱敏 JSON：

```json
{
  "generatedAt": "2026-09-11T00:16:00+08:00",
  "nodes": [
    {
      "id": "n_001",
      "parent": null,
      "submittedAt": "2026-09-10 19:20:00",
      "label": "A001"
    },
    {
      "id": "n_002",
      "parent": "n_001",
      "submittedAt": "2026-09-10 19:26:00",
      "label": "A002"
    }
  ]
}
```

字段含义：

- `generatedAt`：这份数据快照的生成时间；
- `nodes`：要展示的节点列表；
- `id`：公开节点 ID，不要用数据库主键或真实用户 ID；
- `parent`：上级节点 ID；没有上级时为 `null`；
- `submittedAt`：节点发生时间；
- `label`：节点上显示的短标签。

前端会根据 `parent` 自己计算层级，根据 `submittedAt` 自己计算时间位置。

## 数据安全原则

如果这个页面公开访问，数据文件里不要放：

- 可直接识别个人的号码全量值；
- 真实用户 ID；
- 数据库主键；
- 邀请链接参数；
- 问卷答案或聊天正文；
- 任何数据库、服务器或连接凭据。

建议后端生成稳定但不可反推的公开 ID，例如 `n_001`、哈希 ID 或业务无关的随机 ID。

## 运行示例

```bash
cd demo
python3 -m http.server 8080
```

然后打开：

```text
http://127.0.0.1:8080/
```
